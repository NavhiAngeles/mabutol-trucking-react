New office users
  Add Office User requires a Philippine recovery mobile number (09... or +639...).
  manage-office-users creates the email/password login and the canonical Auth
  phone on the same user. It uses phone_confirm:true as ADMINISTRATIVE ENROLLMENT:
  this does not mean a person has already completed an SMS check. An active admin
  already has password-reset authority and must designate the correct user's
  own number. Possession is proved by SMS on EVERY self-service recovery.
  Confirming the admin-enrolled Auth phone avoids the provider's unconfirmed-phone
  OTP signup path, which can replace the existing password with a temporary one.
  Email remains the login identifier; no email is sent or needed for recovery.

Existing office accounts
  User Management > Recovery Phone loads the actual Auth enrollment separately
  from public.users.phone. An active administrator may enroll/replace this number
  for an office account, including their own. Duplicate numbers are rejected by
  Supabase Auth. A stale expected phone is rejected before update; Auth has no
  atomic compare-and-set API, so overlapping admin enrollment remains a limitation.
  Ordinary Account/Contact edits never change recovery authorization. No existing
  numbers are inferred/backfilled, and no accounts are automatically converted.

Forgot Password
  Enter registered phone -> request SMS -> verify six-digit code -> existing
  authenticator challenge if required -> new password -> return to normal login.
  signInWithOtp uses shouldCreateUser:false and SMS; verifyOtp uses type:sms.
  Codes/expiry/rate limits/failed attempts are verified by Supabase Auth, not JS.
  The Auth send-SMS hook uses the existing TextBee integration. No custom OTP
  storage or service key is introduced into frontend code.
  A confirmed SMS session must match the requested Auth phone and an active
  admin/staff users row before this UI allows password update. Customer/driver,
  inactive, changed-phone, wrong-code and expired-code attempts fail closed.
  The recovery client is memory-only, does not replace the existing office
  session, and is signed out locally after completion/cancel. Reload starts over.
  Existing authenticator MFA is preserved, including newly enrolled factors.
  Never persist passwords, SMS codes or recovery tokens in URLs/local storage.
  Unknown/denied/rate-limited request results have the same public message; network
  errors are generic. This is UI enumeration protection, not constant-time API
  behavior or a delivery receipt. A 60-second local resend cooldown complements
  authoritative provider limits. Cancellation preserves existing office sessions.
